# 审核与修改

## 审核顺序
1. 检查任务范围，确认教材小节、具体课时和页数。
2. 对照已确认范围和实际页面，检查必需知识、目标、教学任务和检验练习，并检查栏目顺序；覆盖表仅在确已提供时辅助使用。
3. 对资料引用的关键定义、公式、题目和图形读取完整内容并逐项核对。
4. 检查解答、答案及学生页面的呈现顺序。
5. 检查基础任务的支架与反馈，以及选讲任务的新增要求。
6. 报告具体问题与修改要求。

## 资料相关性
相关性按内容核对。检查页面属于当前教学范围、引用是否真实支持对应表述、题干条件有无遗漏、图号及图片是否匹配。资料编号存在只表示能查到记录，仍需读取其内容。

### 资料是否转成了有效教学内容

对照页面和实际读取的资料，检查选题是否服务于目标、核心例题是否主要依赖本课知识、训练与示范是否有合理联系，是否只是按原栏目取第一题或堆积重复题。

完整性审核分开判断：知识完整性必须通过，资料使用不要求穷尽。逐项核对校本知识回顾，检查核心知识、必要条件、核心方法及各核心目标是否有实际内容承接；不得因没有采用全部题目而退回，也不得因题量较多而直接认定完整。

对每道已选典例逐问对照原题，核查全部题干、条件、小问、对应讲解和答案；缺失小问属于完整性问题。未选用的典例不要求补入。仅采用一道典例时检查它的目标覆盖范围及其余目标是否由其他活动补足，不单凭“一道太少”判错。

检查是否以本课校本内容组织讲解、训练和巩固，教材是否承担知识核对与必要辅助，全解是否解决具体讲解缺口。不能只引用一条校本资料却实际照教材或全解目录展开整课。也不强制校本引用占比、题数或页数，不为体现主次而保留校本错误。

替换校本核心题或增加补充内容时，核对是否确有完整性、正确性或教学目标依据；等价且有依据的调整不因偏离原目录被判错。教材全解未提供不自动构成阻断，冒充已读取全解或缺少关键依据才指出具体问题。

沿共同路径抽查实际讲解缺口。对标称使用全解的内容，回读相关条目并对照相应页或小问，检查出处能否定位，以及指导是否转为学生能使用的任务、提示或反馈。只有检索命中或来源备注时，依据实际页面判断落实程度。找不到适用全解时，检查现有教材、校本或自编支架是否足以解决缺口。有问题时在现有 issues 中指出具体目标、页码或小问、缺失的依据或教学处理，以及修改动作。

检查重难点是否落实为比较、反例、提示或中间步骤，并有对应检验。不要机械要求每个题目同时包含所有干预方式。

检查改编是否保留数学条件、题图和解答对应，变式是否重新解答、自编内容是否误标为资料原文。对“已核验”说明区分原文核对、模型推导、工具验证、图形核对与人工确认，不能将一种核验扩大为全部验证。

当前不强制独立 MaterialPlan、使用台账或覆盖报告。依据实际传递的方案和可读取资料核对设计，追溯到原文片段、题目或页码；不因缺少中间记录退回，不宣称看过未提供的记录。有问题时指出页面、依据及需要改变的实际内容，不仅要求“补一份分析报告”。

自编提问可以联系当前知识，变式要说明使用的知识并检查条件与解答。发现页面主体超出本次课时且没有任务依据时指出具体内容，不只给整套课件一个笼统相似度分数。

## 核查概念形成与当堂理解

1. **停在学生首次判断前。** 指出当时可见的对象、条件和待完成的动作。核对材料是否足以支持所问的判断，后续总结能否回指材料。直接讲授的术语或约定，改查后续是否有辨析或使用任务。动画次数、问题句数量均不能证明学生经历了概念形成。
2. **从共同目标反查页码和小问。** 逐项比对目标动词与首次独立作答时的实际动作。目标要求解释而学生只需选择，或目标要求操作而学生只需观看时，指出缺少的表现，优先改写已有小问或调整揭示时机。一题可覆盖多项目标，但应能指出每项目标对应的回答或操作。
3. **用部分正确的回答检验反馈。** 对核心难点，检查判定依据能否区分碰巧答对与理解条件，反馈能否引导学生自己修正。若有缺口，意见写明目标、页码或小问、具体缺口及最小修改动作。审核评价课件提供的机会；学生实际掌握情况须依据课堂作答判断。

沿用现有分级：独立任务提前泄露答案归入“阻断”；核心目标缺少独立检验，或核心概念的关键条件缺少必要支架，归入“需调整”。已有有效任务时直接指出其位置，无需另设练习页或额外提交覆盖表。

### 核查综合任务前的支架

任选共同路径中首次使用某项新方法的综合任务，定位学生必须独立完成的关键一步，回查该步在哪里得到示范、练习或反馈。对依赖图形或工具的步骤，检查学生在对应时刻能否指出基准、关键标记和变化依据。教师直接演示后有独立作答机会、或学生在综合题的小问内逐步建立方法，均可通过。发现缺口时指出具体页、小问和缺失的操作或证据，沿用本文件的问题分级。

## 课时任务主线专项审核

按 [课时任务主线设计](teaching.md#lesson-task-thread) 从导入、关键转折和最后的独立任务回查整课。按实际页和小问判断，允许统领任务或相互关联的局部问题两种组织方式。

| 审核维度 | 查找的页面证据 |
| --- | --- |
| 学习需要 | 关键新知识出现前，学生面对的问题、已有办法以及新要求清楚可辨。 |
| 环节衔接 | 前一任务的产出、条件、难点或方法在后一任务中有实际用途；也可用并列局部任务分别承接不同目标。 |
| 判断机会 | 核心难点有学生判断及依据反馈。正式定义或直接讲授之后有针对适用条件的辨析或检验。 |
| 任务推进 | 引入新知识后，学生能更准确地表示、有效地操作或充分地解释，并在后续任务中实际使用。 |
| 自主运用 | 条件齐全，题面仍留给学生至少一项会影响解题的决定。检查首次作答时可见的提示。 |
| 基础路径 | 移除选讲内容后，基础任务、必要方法、独立运用、反馈及小结仍可完成。 |

统领任务只在导入和小结出现时，沿中间页检查它是否改变了实际问题、学生行动、题目选用或反馈。若这些环节各自孤立，指出需重接的页码及可复用的前一项学生产出。无单一统领任务时，按局部问题的学习逻辑判断整课组织。

主线问题沿用现有等级和 issues 字符串。指出两处环节的页码或小问、缺失的学习联系或自主判断，以及最小修改动作。内容正确性、必要条件和答案显隐由对应规则继续判断。专项回归见 [任务主线案例](design-cases.md#lesson-task-thread-cases)。

## 学生任务与答案

有分析组时，检查已按 [分析框约定](page-model.md#分析框的显示约定) 安排带边框、明确标“分析”的独立区域。无框、缺标题或将答案混入框中，应指出对应页及修复要求；仅收到方案时只能核对安排，不能宣称已看到实际框或点击效果。没有分析组的题不因没有分析框被退回。

页面设计按 [页面格式](layout.md) 核对字体层级和容量策略。不能为保留题量而计划使用过小正文、表格或图中标注；需要时调整布局与步骤，保留必要条件和全部已选小问。只有逐页JSON且无字体字号字段时，不编造新字段或宣称已验收实际字号，具体字体、字号及溢出由制作与成品检查落实。
问题需要可执行，图和条件足够作答。答案应与小问对应。初始练习图中若已显示教师填答、红色解析或答案连线，应指出具体页和图形。

按 [页面制作的分步呈现](page-model.md#分步呈现) 检查初始态与每次揭示：需要学生先尝试的任务，答案及有反馈作用的提示、推导、结论、答案图不能以0直接上屏；普通题默认同页点击揭示，不仅放在备注或机械拆成题目页与答案页。长计算、证明、作图的必要拆页与明确要求的静态步骤稿按该规则的例外判断。教师备注不能弥补页面遗漏的关键条件。

逐项检查题干、选项、表格预填项及教师版图片中的结果、红字与完成图，不能只检查answer块。已知条件和原题示范不属于待隐藏答案。表格分组反馈不得提前泄露后续题目。只收到JSON时审核的是揭示计划，不能据此宣布实际动画通过；成品是否初始隐藏及点击有效交由成品验收。

同一题同阶段的对象允许同序号同时揭示，不因重复编号直接判错；不同题目默认逐题反馈，不能把多题分析或答案机械绑定为同一次点击。同题跨页可以复用原图，不把重复图片一律当作串题；需检查题目归属与图中变更。

带分析的例题或讲解题，检查“题目 → 分析 → 答案”三组是否独立安排显示顺序；分析应是可上屏的简短引导追问，来源应为三层 PPT 引导（关键问题、递进提示、反思迁移），而不是把五维详细分析（考点、条件、思路、难点、拓展）整段搬上屏。没有对应现成引导的题直接采用“题目 → 答案”，不自行补写分析；变式题也允许省略分析，不能仅因缺少分析组退回。省略分析不免除答案隐藏；有分析时答案必须晚于本题最后一条分析出现，不能与最后一条分析同时显示。默认整框一次出现；0、1、2只是单题示例，按全页实际点击顺序核对。仅审查方案时检查 reveal_order 计划，不宣称动画已经生成。

默认检查学生标题、栏目和正文是否误用章节/课时代码作独立小标题或分界，改为知识主题；必要图号、小问编号与数学数值不是清理对象。按 [题号、出处与变式标注](page-model.md#题号出处与变式标注) 核对例1、例2等连续编号、同题续页一致、可见出处准确，以及变式基题可定位、改动真实且重新解答；不接受只有“例”或笼统“由教材变式”的标注。

**出处不可见按阻断处理。** 出处只写在 speaker_notes、只体现在 material_ids、只藏在教师版截图里，或写成“见原题”“同前”、只在首标后续页省略的，都要求补上学生可见的文字标注；不要因为“备注里已经写了”就放过。审核时逐页核对多页例题的每一页是否都带出处。

设计阶段检查图引用是否准确且有对应素材；制作后的图片是否真的嵌入由成品验收检查。只收到JSON时不能宣称已检查PPTX图片，也不能以JSON不包含二进制图片为由退回；收到PPTX后，不能把路径文字视为已插图。

## 分别审核内容与学习过程

按 [数学表达](math-checks.md) 的内容类型检查概念、条件、依据、推导和结论；再按 [教学组织](teaching.md) 检查核心目标是否有学生思考、操作、表达、验证或应用的机会，以及问题、方法和反馈能否衔接。不能仅因解答完整就判定学习过程完整。

对标为探究或承担探究作用的活动，用六要素核查问题、行动、观察、证据、推理与结论之间的联系。可跨页或合并表达，不要求独立六页或六个标签；普通练习没有六步也不因此退回。检查的是实际任务，不只检查是否出现“探究”标题。

教师示范本身不是错误；只有当关键目标完全没有相应学生任务，或所谓探究仅靠点击展示结论、缺少实际行动与推理时，才指出具体缺口及修复要求。针对性检查缺少的必要环节，不要求所有页补齐全部学生行为。

本阶段审核学习机会与反馈设计，不能在未开展课堂时宣称学生已掌握、学习效果已验证；数学正确性核验与教学活动有效性设计也不相互替代。

## 四项设计检查

| 检查 | 具体判据 | 有问题时指出什么 |
| --- | --- | --- |
| 方法形成 | 核心难点有帮助理解依据的问题链，而不只是完整步骤或改成问句 | 哪个关键选择未解释，学生需要完成什么任务 |
| 必要图形 | 任务必需图存在且关键状态、点线标注与文字对应 | 哪页缺什么图形信息，不能只说“增加图片” |
| 学生行动与反馈 | 答案前有具体尝试和可判断产出，关键反馈说明依据 | 哪个任务只是“请思考”，哪里只有答案没有必要反馈 |
| 练习组织与总结 | 练习有能力递进或内容互补，总结回指本课方法与依据 | 哪两题无新增作用，或哪个方法缺少检验与总结 |

问题链只在存在核心认知障碍时要求展开；无需每题探究、每步新图或统一五级题组。教学设计有其他等效安排时允许差异，不能以没有复刻参考课件的页序为由退回。

辨别三类伪落实：将步骤改成“下一步是什么”但未处理依据；只有最终图却不能支撑必需操作；只有“请思考”而无具体任务、可判断产出或反馈。判断必须基于实际活动，不按问题数量、图片数量或出现关键词打分。

检查数学依据是否适合已学内容：不得为了要求解释尺规作图正确性，强迫尚未学习相应定理的课时使用全等证明；操作验证也不能伪称严格证明。图片缺失属于设计还是制作问题要分清：方案没有安排必要图形须调整设计，已安排但成品漏图回制作；未收到成品不能假称已检查播放和视觉效果。

按 [专项验证案例](design-cases.md) 可以检查上述边界；该文件是验证方案，不代表已运行测试或验收通过。

## 问题级别与当前接口

| 级别 | 示例 | 处理 |
| --- | --- | --- |
| 阻断 | 数学错误、关键条件缺失、图文不符、原题被错误改写、已选典例缺失小问、答案提前泄露 | 必须修正，不能定稿 |
| 需调整 | 核心目标未覆盖、活动缺少必要支架、课堂容量有明确依据表明不合理、违反已约定栏目或明确页数 | 指出依据，修改教学设计后复核 |
| 允许差异 | 题目数量不同、例题顺序调整、提示方式不同、未指定精确页数时的页面数量不同 | 满足目标与明确约束时，不仅因此退回 |

当前运行时仍使用 approved 和字符串列表 issues，不新增 severity、warnings 等字段。issues 只放阻断和需调整问题，可用“[阻断]”或“[需调整]”前缀；有任一项则 approved=false。只有允许差异或非必要建议时 approved=true、issues=[]；独立建议仅在有通道时记录，不在 JSON 外追加文字。

待确认是证据状态，不是第四个审核等级。缺少影响数学正确性的依据归为阻断；范围或安排冲突影响设计时归为需调整。指出需要补什么或可如何替换，不能把所有未核对细节一律升级为阻断。

区分明确约定与教学偏好：新授栏目顺序、知识回顾核心知识全覆盖、已选典例完整和用户指定页数仍需满足；允许例题在所属栏目内按教学逻辑调整顺序，不要求沿用原目录。目标已覆盖时，不因另一道相似题没有选用而要求补齐全部典例；不能以“我更偏好另一种提示”代替缺少支架的具体证据。

课堂容量问题应依据已知课时、任务所需操作、解答复杂度或可验证的页面容量指出；没有时间信息时不凭题数或页数武断判定超时，不编造学生完成时间。优先给出能解决问题的局部调整，不强制生成唯一模板式答案。

## 审核输出
遵守当前角色指定的审核格式，当前接口使用 approved 和 issues。通过时 issues 为空；未通过时每条意见指出页码、问题、涉及的资料编号及明确的修改要求。资料编号不适用时直接说明数学或结构问题。

格式、引用或数学条件没有确认且影响交付正确性时，明确待核对项，避免将不确定性当作已通过检查。核实图号和路径不等于看过图片；但没有看图工具也不构成禁止引用所有原图的通用理由，指出具体依赖图中信息的条件或结论。

## 设计返工
按意见修改实际内容，返回完整逐页方案。修改题干时同步更新图形、提示、步骤和答案。资料引用继续使用本次工具返回的有效编号，页码和总页数仍满足任务要求。

先分清可通过改写修复的问题和缺少依据的问题。缺少原图说明、未提供的公式或无法消解的课时冲突，反馈需要补充的具体信息，不反复改写同一段落冒充问题已解决。遵守调用方返工上限，不承诺技能本身能暂停或恢复程序。

对证据缺失说明能否通过重查或替换解决；无合理替代时，issues 写明需要补充的原题、公式或图形条件，而非只要求“再次完善”。停止及恢复以调用方实际协议为准，不能声称现有 approved/issues 已自动区分可修改错误与需输入状态。

## 制作检查
用审核后的内容生成页面。发现内容错误时回到内容修改和审核，排版问题按页面调整。保存确实生成的文件及检查结果，不用口头“已完成”代替文件。

成品检查按 [成品验收](delivery-checks.md) 执行；approved=true 不等于PPTX生成或版式验收通过。

## KnowledgeMap专项审核

按 [KnowledgeMap](knowledge-map.md)核对共同目标全覆盖、实际教学依据、节点归属、分类标准、条件和结论、关系方向、数学依据以及基础/选讲双路径。每条issues写出节点或关系ID、问题类型、对应教学页、证据和修改动作；沿用approved/issues，不增加审核输出字段。只有JSON时不宣称已检查图形可读性；视觉问题由成品检查另行报告。
