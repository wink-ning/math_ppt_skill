# 本课知识结构图（KnowledgeMap）

## 适用范围和职责

每份新授课必须在“课堂小结”中安排一张独立的“本课知识结构图”，默认一页，计入教学页数；它是页面角色 KNOWLEDGE_MAP，不是第十个栏目。仍保持课堂小结→思想方法→结束页的既定顺序。“最后的知识总结”不意味着放到结束页之后。复习、自定义课型按用户要求；如提供图谱也执行同样的数据校验。

设计角色在教学内容基本确定后提取节点、关系和目标映射；审核角色检查数学逻辑及双路径完整；制作角色绘制实际对象；成品检查分别记录结构与视觉结果。不新增智能体或独立流程节点。

## 从实际教学提取知识

以本课核心主题为唯一根；一级分支按实际知识类别、方法或应用组织，通常由二级节点表达具体知识，必要时增加层级。内容简单且一级分支已表达具体知识与关系时，可用根主题加一级知识节点。按共同目标和数学关系决定深度，避免用重复分类或标题凑层数。不固定分支数量和名称，不复制教材目录、页面标题或例题清单。候选内容包括概念、分类、表示、性质、方法、依据、易错辨析和应用，不要求每课全部出现。

节点使用短语和必要公式，保留定义条件、量的范围和单位。不给完整教师解析，不以“定义、练习、小结”等栏目名冒充知识。父子关系表达归属；定义、分类、条件、推导等关系要有依据。支持跨分支关系，不能为了凑树形而改写数学逻辑；双向关联不等于双向推导。

用图谱做一次可复述性检查。学生沿着任一共同目标分支，应能读出至少一个实际讲过的判定条件、关系式、关键步骤或使用条件。节点若只写「度量方法」「重要性质」之类目录词，补成能够复述的具体知识。容量紧张时优先保留会改变判断或计算结果的条件与数值。

所有CORE目标至少有一个CORE知识节点；所有非根节点记录之前实际教学页码。不得用图谱自身或目标页自证“已经教过”。不要求覆盖每道练习。先检查课件核心知识是否漏入图谱，再检查图谱是否增加未讲知识；发现缺口修复教学或图谱，不靠补节点掩盖漏教。

可选节点明确显示“深入选讲”或“拓展挑战”；移除所有可选节点后，基础主体仍须连通且覆盖共同目标。共同必需的定义、条件和依据不可藏在可跳过分支。内部层级枚举不直接上屏。

## 正式数据契约

以 agent/models.py 和 common/knowledge_map.py 的JSON Schema为准，以下是本次正式支持的增量字段，旧文档的“不新增字段”仅禁止契约之外的自造字段。

- SlidePlan.objectives：目标列表，每项 id、label、layer（CORE/DEEPENING/EXTENSION）。目标ID与学习目标页的实际目标对应。
- SlidePlan.knowledge_map：title、page、layout、root_id、nodes、relationships。
- Slide.page_role：CONTENT（默认）或KNOWLEDGE_MAP。图谱页 section=课堂小结，title=本课知识结构图；blocks沿用现有必填要求，可放本页真实概述，原生绘制器用knowledge_map绘制，不能把概述代替图形。
- 每个节点：id、label、node_type、layer、parent_id、objective_ids、source_pages。
- 节点类型：topic、concept、definition、classification、representation、property、method、condition、formula、application、pitfall。
- 每条关系：from_id、to_id、type、label。type为contains/classification/definition/representation/condition/derivation/application/prerequisite；label填写学生可理解的中文含义。
- prerequisite方向为“前置依据→依赖它的知识”；不是相反方向。
- source_pages使用当前Slide.page的整数页码，不引入P03等不存在的页面ID。重排后同步更新页码引用。

当前契约要求唯一 CORE topic 根、至少一个非根知识节点、唯一节点与目标编号、有效父节点和关系端点；父子层级及前置依赖不能循环。CORE不能依赖可选父节点或可选前置知识。代码检查有效引用，审核角色另查引用是否真实支持该知识。

旧方案仍可解析和读取；使用新版新授工作流重新交付时须补齐目标和图谱。review/custom未提供图谱不强制补齐，已提供则完整校验。不能宣称新增字段对所有旧新授交付完全无影响。

## 绘制和容量

默认 hierarchical。只选本轮绘制器经确认支持的布局。当前原生绘制器有层级树、radial 和 flow 三种实现，concept_map 与 logic_map 会走水平层级树布局，可用于读取已有数据。对新方案按实际效果选值。括号、树枝、文本框和箭头都可，不强制卡片。优先可编辑PPT文本、原生形状和连接线，其次经核对的矢量方案。不得默认使用图片生成模型生成数学文字整图。

沿用 16:9、本次任务的学校 Logo 要求、深蓝正文与必要强调色。标题32pt，节点默认28pt，较密时最低24pt；关系说明不得小到无法课堂阅读。不把整个图压成小字截图。连接线不得遮住文字，关系标签不造成歧义；可选节点不能只靠颜色区分。

默认一页，先合并同类节点、精简重复语句、调整布局，仍超出容量则反馈问题，未经用户同意不拆为多页、不降字号。与普通长题拆页规则不同，此图单页容量限制优先。

## 制作程序和交付

tools/knowledge_map.py提供 draw_knowledge_map、check_knowledge_map_slide 以及已注册的 build_knowledge_map 工具。外部制作程序先生成完整课件，并为图谱保留指定的一张空白页；调用工具传入完整plan_json、source_file和新的output_file。工具只填写对应空白页，不增加其他教学页，不覆盖原课件；返回实际slide_id、文件和结构检查结果。也可以在外部生成器中直接调用绘制函数。

绘制器根据树的深度和分支容量定位，不固定分支数；交叉关系使用原生箭头和独立中文关系说明。原生文字与连线可分别编辑。数学文本应先核对本轮工具能否正确呈现，可使用经核对的 Unicode 表达；含未转换LaTeX的节点会报错，须由外部公式工具先转换为准确可编辑表达，不把公式代码作为成品。容量预检为估算，不等于渲染可读性检查。

没有整套PPT生成工具时，图谱工具不能凭空生成其余教学页，不声称课件已完成。不得用只返回节点JSON、页面路径或备注代替实际绘制。

## 专项审核与验收

按用户原始要求和已确认课型先查图谱存在性，再核对结构。页面重排或加入独立封面后核对教学页映射，更新关联页码和成品页定位。

内容审核逐项检查：共同目标覆盖、节点对应页面、定义条件及公式、分类和关系方向、未讲知识、核心依赖、可选层级。意见写入现有issues字符串：等级；节点ID/关系；问题类型；对应页；证据；修改动作。纯格式校验不能证明数学正确。

文件结构检查节点、关系、标题、本次任务的 Logo 要求及实际 slide_id，检查它们确实是PPT对象、没有遗漏或仅存在备注。视觉检查另查节点文字和公式完整、线条穿字、交叉歧义、边界及可读性。未渲染、未播放必须分别标记未检查，不将节点对象存在称为“已验证渲染”。用户要求不渲染时不启动渲染，但继续执行结构检查。

## 最小数据示例

```json
{
  "objectives": [{"id":"O1","label":"能准确描述本课概念及成立条件","layer":"CORE"}],
  "knowledge_map": {
    "title":"本课知识结构图","page":6,"layout":"hierarchical","root_id":"K0",
    "nodes":[
      {"id":"K0","label":"实际课题","node_type":"topic","layer":"CORE","parent_id":null},
      {"id":"K1","label":"实际概念","node_type":"concept","layer":"CORE","parent_id":"K0","objective_ids":["O1"],"source_pages":[4]},
      {"id":"K2","label":"已讲授的完整定义与条件","node_type":"definition","layer":"CORE","parent_id":"K1","objective_ids":["O1"],"source_pages":[4]}
    ],
    "relationships":[{"from_id":"K1","to_id":"K2","type":"definition","label":"定义"}]
  }
}
```

该片段仅说明字段，不能直接作为教学内容；完整SlidePlan还须包含真实slides，图谱所在页设置page_role。layout等字段是后台参数，不机械上屏。
