# 数学课件制作

## 执行目标

把本次教学内容组织为教师可以逐页讲授、学生可以观察和练习的课件。每页包含实际教学内容，题目、图形、提示、步骤和答案相互对应。主题、教材和课时按当前任务填写。

## 资料使用主线

**校本教材为主，教材为辅，教材全解提供指导补充。** 优先读校本的课时安排、知识回顾和候选题，组织本课讲解与练习；用教材核对知识依据并补充必要说明或探究；从共同目标和校本例题识别讲解缺口，再按缺口查阅教材全解并落实到具体任务或反馈。查阅和取舍按 [教材全解的使用规则](references/material-use.md#教材全解从指导到补充) 执行。

这是内容组织和选用的优先级，不是数学正确性的等级。校本题和教师答案仍需核查，不能为迁就主线保留错误。教材全解不替代教材原文，不自动扩大教学范围。

## 页面硬约束

以下四条是每次设计都必须落实的底线，细则见对应文件。

1. **学校 Logo**：默认每一页都必须有，只有用户明确要求时可省略。用 [蓝色版](assets/logo/logo01.png)（红色主题可用 [红色版](assets/logo/logo02.png)），右上角，保持比例、不遮挡内容；不能用文字、路径或备注代替图片。默认将封面内容并入课题页；用户明确要求时允许独立封面，作为标准栏目之外的额外页，不计入指定的教学页数。不得自行增加目录或素材页。按 [学校 Logo](references/layout.md#学校-logo) 执行。
2. **字体字号**：中文标题黑体32 pt，正文微软雅黑28 pt，较密推导与表格24 pt，数学字符 Times New Roman、公式优先 Cambria Math。容量不足先调整内容与布局，不持续缩小字号。见 [页面格式](references/layout.md)。
3. **答案初始隐藏**：有待学生作答或探究的任务，答案、提示、推导和答案图默认不显示，同页点击后按教学时机揭示；不能题目与答案同时上屏，也不能把答案只放教师备注。普通题不默认拆成题目页和答案页。
4. **分析框**：带分析的例题按“题目 → 分析 → 答案”三部分呈现，分析放在带清晰边框、标“分析”标题的独立区域，边框、底色、标题与内容初始一并隐藏、同步出现。标准分析框使用本题已核对的三层 PPT 引导。缺少现成引导时省略标准分析框，仍可设计必要的学生问题与普通提示。区分方法见 [分析框的显示约定](references/page-model.md#分析框的显示约定)。默认分析整框一次出现，多题逐题反馈，揭示顺序按全页点击连续安排。

分步呈现的字段写法、长计算与作图的拆页边界、静态审阅稿与制作能力不足的处理，统一按 [页面制作的分步呈现](references/page-model.md#分步呈现)；写了 reveal_order 不代表已经实现动画。

## 上屏表述约定

默认用知识主题或学生任务命名页面，不把教材章节/课时代码（如“第X章”“X.Y”“X.Y.Z”这类定位编码）当作独立标题、栏目名或正文分界。例题必须写“例1、例2”，并紧跟真实出处——**出处必须学生可见，是硬性要求，不得只写在教师备注、material_ids 或图片里**；课时代码在出处标签中出现属于本条唯一例外。变式须标出基题与改动。规则见 [题号、出处与变式标注](references/page-model.md#题号出处与变式标注)。题号、小问号、必要图号及数学数值不做标题清理。

已选用并引用的原图，生成PPTX时必须嵌入对应页面，不能只写路径或“见原图”；只交付JSON时保留准确引用，不声称已插图。细则见 [页面制作](references/page-model.md) 与 [成品验收](references/delivery-checks.md)。

## 本课知识结构图

每份新授课须在课堂小结中安排独立的“本课知识结构图”，page_role=KNOWLEDGE_MAP，图谱页在指定教学总页数内分配，属于课堂小结栏目。根据实际讲授内容生成根主题、分支、知识节点和有依据的关系，覆盖全部共同目标并保留选讲标记。通过正式objectives和knowledge_map字段交接，不能只交普通列表。生成、制作与专项校验按 [KnowledgeMap规范](references/knowledge-map.md) 执行；容量不足反馈，不擅自拆页或缩小字号。

## 两条完整性

- **知识完整性（必须）**：本课校本知识回顾全部核对，核心目标全部落实，已选典例完整保留各问。边界与选题规则见 [资料使用](references/material-use.md)，不以题量判断质量。
- **学习过程完整性（必须）**：数学内容按 [数学表达](references/math-checks.md) 核对；教学活动按 [教学组织](references/teaching.md) 检查学生参与和“问题—方法—验证”闭环。真正的探究才用 Question / Action / Observation / Evidence / Reasoning / Conclusion 六要素核查，可跨页衔接，不强制每页套用。

**核心新概念的形成。** 对理解依赖关键条件或变化过程的新概念，明确学生在结论揭示前能观察什么、作出什么判断，以及这些观察如何支持规范表述。术语和符号约定可直接说明，再让学生辨析其适用情形。

**共同目标的当堂检验。** 每项共同目标都应能定位到一次与目标动词相符的独立作答机会。检查学生看到的条件、需要给出的回答或操作，以及判断依据。可复用已有例题的小问或练习，一项任务可覆盖多个目标。

设计时重点判断：核心方法是否需要形成过程、任务是否必须有图、答案揭示前学生实际做什么、保留的练习是递进还是互补。落到实际问题、图形、提示和反馈，不以“已设计探究”或完整解析代替。

综合任务若同时要求学生作出多个本课新学的判断或操作，先检查它依赖的关键一步是否已有可用的示范与检验。缺口优先用原题的小问、短辨析或关键图形状态补足。设计和审核共同沿用 [从示范到独立任务](references/teaching.md#从示范到独立任务)，并在小结写出学过的关键条件、关系或公式。

## 先确定本次任务

从输入中确认年级、课题、教材章节、小节内的具体课时、页数及交付形式。区分“一个小节”和“其中一课时”，有多个课时代码时先明确范围；准备说明中的缺失项要保留，不能用猜测替代教材版本或未读取的题目。课时范围与覆盖按 [课时范围与覆盖](references/scope-coverage.md) 整理；目录只用于定位，知识范围由设计角色读原文后核定。

## 按角色工作
- 教学准备：理解任务，调用资料查询，整理范围、可用编号和缺失项。输出准备说明。
- 课件设计：读取候选资料，判断选用理由、教学处理与任务层级，组织讲解、练习和页面，保留最小可核对的来源引用。输出完整逐页方案，允许回查资料和调整选用。
- 内容审核：对照逐页方案和实际可用资料，检查数学内容、目标覆盖、图题配对及分层路径的完整性，区分阻断、需调整和允许差异，按规定格式返回意见，不以个人教学偏好替代质量标准。
- 课件制作：用审核后的方案制作页面。内容审核与成品验收分开，文件生成后按工具能力检查结构和实际显示。

只完成当前角色负责的阶段；输出结构、工具参数及审核格式使用调用方给定的接口。

## 按角色加载参考规范

优先由调用方预加载本文件、[核心规则注册表](contracts/rules.json) 和适用参考。当前环境没有预加载时，先读本文件和规则注册表，再按本轮角色读取表中 `role_references` 对应的 `required`，再按课型、图谱和专项回归等实际条件读取 `conditional` 中命中的参考。条件从原始需求和上游确认的课型、范围、任务、选材及交付要求判断，结合当前结果核对。应有项未出现在结果中时仍须执行存在性检查。角色职责为教学准备 `preparer`、课件设计 `designer`、内容审核 `reviewer`、课件制作 `builder`。承担多个角色时，在进入相应阶段前补读其规范；调用方已提供完整正文时可直接使用。

本轮适用规范读取不完整时，先补读。仍无法取得时，指出缺失的规范及受影响的检查，通过调用方已有接口反馈。规则注册表提供阶段、来源、适用条件和验证方式，专项 Markdown 提供具体判据。调用方未接入预加载、规则解析或审核日志时，据实说明执行能力。

## 设计顺序

1. 明确课时范围及共同目标，列出范围依据、可用资料和缺失项；明确小节与具体课时的边界。
2. 理解校本候选题和知识回顾，用教材核对条件与结论，定位讲解缺口并按资料使用规则回查教材全解。
3. **先确定 [课时任务主线](references/teaching.md#lesson-task-thread)。** 选统领任务或相关局部问题，确定学生在关键转折处需要什么知识、前后任务怎样衔接、最后哪一步由学生自主决定。以实际任务与页码作为审核依据。
4. 围绕主线安排局部问题链、必要图形状态、学生行动和反馈。按教学用途选择完整校本例题与独立练习，再决定哪些内容进入共同路径或选讲。
5. 按 [页数与容量规则](references/teaching.md#page-capacity) 预检题面和最终显示状态。用现有 SlidePlan 编排页面、登记 `material_ids`、标明自编内容，按课型安排知识结构图。
6. 提交内容审核前逐项对照知识覆盖、资料来源、图题与分步呈现。制作角色依据审核后的内容生成文件，按 [成品验收](references/delivery-checks.md) 分别核查实际文件及可执行的显示检查。

## 新授课结构
课题页 → 学习目标 → 导入 → 新知探究 → 课堂训练（可选）→ 新知巩固 → 课堂小结 → 思想方法 → 结束页。

section 必须逐字使用上述栏目名称（“导入”也可写“情景导入”“情境导入”或“导入新课”；其余栏目不要自造名称，也不要把内容塞进“其他”“补充”类栏目）。除可选的课堂训练外，每个栏目独立成页，思想方法和结束页分别安排；一个栏目可连续多页，例题归入新知探究。教学页数按任务要求分配，保持栏目顺序。独立封面不占教学页数，也不代替课题页；交付时分别说明教学页数、额外封面页数和文件实际总页数。

栏目数量或实际页面容量与指定页数冲突时，按 [页数与容量规则](references/teaching.md#page-capacity) 取舍，保留全部必需栏目。复习或自定义结构只在用户明确要求时使用。

## 交付标准

逐页方案须包含能直接展示的题目、公式、图形和解答，不使用“此处放例题”等占位语；教师备注承载讲解提醒，不替代页面正文。资料中的公式或题图未能确认时指出具体待核对内容。只有文件确实生成、检查实际执行后，才报告相应结果；缺少生成工具时交付制作方案并说明文件尚未生成。

来源追溯做到最小可验证即可，不要求输出接口无法承接的 MaterialPlan、范围清单或覆盖表。本次正式增加objectives、knowledge_map和page_role；具体契约见KnowledgeMap规范。不得新增这些正式契约之外会被运行时忽略的 JSON 字段，不在要求纯 JSON 的回复前后附加说明。技能中的检查要求不等于已有工具实现，未执行项标明未检查。

## 缺少关键依据时

先重查已提供资料及定位信息；仍不足时，优先换用能实现同一目标且内容完整的题目或活动，并同步全部引用、条件与答案。替换不能漏掉必需知识、删去已选典例的小问或隐去本课核心目标。

无法合理替换且影响正确性或覆盖时，不定稿、不以占位文字或猜测补齐。使用调用方实际提供的停止或补充信息协议，指出缺失对象、影响及需要的资料；不要自行发明状态字段或异常返回 JSON。技能本身不能完成暂停和追问；不能将普通方案输出或格式校验失败声称为“已暂停等待”，也不能声称审核 issues 已具备自动停止返工机制。

## 多班型共用一份课件

生成一份多班型共用的 PPT。共同必学内容形成完整主线，以“基础必学／深入选讲／拓展挑战”表达不同深度；层级依据本次教学目标、已学知识和后续依赖判断，不预设任何知识点必属某一层级。教师按课堂进度与学生表现选择是否展开选讲任务。细则见 [分层规范](references/difficulty-layering.md)。

按实际教学需要设置可选层级和任务数量。审核须分别检查仅基础路径与基础加选讲路径的完整性。
